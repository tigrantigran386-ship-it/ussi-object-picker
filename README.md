# USSI Object Picker

Обёртка над [UniversalSynSaveInstance](https://github.com/luau/UniversalSynSaveInstance) с **деревом объектов**: ты раскрываешь сервис, отмечаешь конкретные модели/парты/скрипты — и сохраняется только выбранное, в один файл.

## Запуск в экзекьюторе

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/tigrantigran386-ship-it/ussi-object-picker/main/ussi_object_picker.lua"))()
```

Короткая ссылка: https://tinyurl.com/248tomz2

## Как пользоваться

1. Нажми `+` у сервиса — ветка раскроется, внутри видно объекты.
2. Тапни по строке объекта — поставится галочка. Можно набрать объекты из разных сервисов.
3. Снятие галочки внутри выделенной папки = исключение: папка сохранится, а этот объект вырежется.
4. Жми «ЭКСПОРТИРОВАТЬ». Файл появится в папке workspace твоего экзекьютора.

## Форматы

| Формат | Что получится | Как открыть |
|---|---|---|
| `.rbxl` как карта | объекты на своих путях (`Workspace/Папка/Модель`), остальное отрезано | Studio → File → Open from File |
| `.rbxm` как модель | только выбранные объекты списком сверху | Studio → File → Insert from File |

Если в экзекьюторе нет `buffer`, скрипт сам сохранит в XML (`.rbxlx` / `.rbxmx`).

* **Имя файла с плейсом и ID:** `USSI_<НазваниеПлейса>_<PlaceId>_<объект>.rbxl` — сразу видно, откуда дамп.

## Чего скрипт не может

`ServerStorage`, `ServerScriptService` и серверные `Script`/`ModuleScript` клиенту не репликуются (FilteringEnabled) — в дереве они пустые. Это не баг.

## Предупреждения

* Инжект-скрипты нарушают ToS Roblox и детектятся Hyperion — используй твинк.
* USSI скачивается с ветки `main` чужого репозитория и тянет зависимости из `SomeHub` — сторонний код, который автор может обновить в любой момент.
* Чужие ассеты в своём проекте — нарушение авторских прав и DMCA-риск.


## Почему одни скрипты работают, а другие нет

| Что | Видно клиенту | Работает после дампа |
|---|---|---|
| `LocalScript` в `StarterPlayerScripts`, `StarterGui`, `ReplicatedFirst`, `PlayerScripts` | да | да, если включить через фиксер |
| `ModuleScript` в `ReplicatedStorage`, `Workspace` | да (байткод) | только декомпилированный текст, часто нужно чинить |
| Серверные `Script`, дети `ServerScriptService`, `ServerStorage` | нет | нет и не будет |

Серверные скрипты клиенту не репликуются — в файле от них остаются только имена.
Декомпилированные скрипты (опция `Decompile`) — это псевдо-код из байткода,
он часто не компилируется без правок. Полностью рабочий файл получается только
у uncopylocked-плейсов (если он выложен автором) или open-source проектов.

## USSI_Fixer.lua — что это

Рядом с дампом кладётся `USSI_Fixer.lua`. Открой дамп в Studio, вставь фиксер
в Command Bar (View → Command Bar) в режиме редактирования — он:

1. включает спавн персонажа (`CharacterAutoLoads`),
2. чинит камеру и `CollisionFidelity` у мешей/юнионов,
3. чистит сломанный `Chat`/`TextChatService`,
4. переносит `LocalScript` в `StarterPlayerScripts` (иначе они не выполняются),
5. создаёт `ServerScriptService/_DumpStubs` — заглушки ремоутов, чтобы клиент
   не зависал на `InvokeServer`, и логирует вызовы (`[remote] ...` в Output) —
   по этим строкам виден протокол игры, который можно реализовать самому.

Отдельный файл: `studio_fixer.lua` можно запускать и вручную.
